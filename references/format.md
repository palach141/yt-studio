# Оформить видео

Автор даёт ссылку на уже загруженное видео (или файл его субтитров) и получает одним ответом всё,
что вставляется в YouTube Studio на странице видео: название с текстом для обложки, описание с
главами, теги. Это не новый режим, а сборка трёх: главы и описание из `references/publish.md`,
заголовок из `references/package.md`. Прочитай оба файла - правила там, здесь только порядок,
команды и форма ответа.

Название и описание - текст от имени автора: правило о голосе из SKILL.md действует. Главы -
аналитика, voice.md для них не нужен.

## Порядок

1. **Субтитры.** По ссылке:

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/fetch.py captions "https://youtu.be/ID" --lang ru --out yt-work
   ```

   `--lang` - язык канала. Нет yt-dlp - инструмент напечатает, как поставить; предложи это одной
   командой или попроси `.srt`/`.vtt` из Studio ("Субтитры" -> три точки -> "Скачать"). Файл от
   автора используй как есть. Если в файле метки стоят внутри фраз на каждом слове, это
   автоматические субтитры YouTube: имена и термины в них бывают искажены - запомни для
   последнего раздела ответа. Прочитай транскрипт целиком до следующего шага: все названия и
   описание пишутся по нему, а не по заголовку, который видео уже носит.

2. **Главы.** Черновик, переименование, проверка:

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/chapters.py yt-work/ID.ru.vtt
   python3 ${CLAUDE_SKILL_DIR}/scripts/chapters.py --check yt-work/chapters.txt --duration 12:40
   ```

   Первой команде - файл, путь к которому напечатал `fetch.py`, или файл автора. Между командами -
   пункты 1-4 раздела "Главы" в `references/publish.md`: убери границы, которые режут одну тему,
   назови каждую главу в 3-5 слов, сохрани блок в `yt-work/chapters.txt` строками `м:сс Название`.
   `--duration` - длина видео, как её показывает YouTube, в формате `м:сс`; если известна только
   из субтитров, возьми последнюю метку времени из файла, округлив вниз до секунды (она чуть
   меньше настоящей длины, проверка от этого только строже). В ответ идёт только блок, прошедший
   проверку. Если ролик в этом разговоре резали или автор ещё собирается резать - действует
   правило 9 из SKILL.md.

3. **Запросы, название и текст обложки.** Сначала выпиши три поисковых запроса, по которым
   видео должны находить, - словами, которые набрал бы зритель, по содержанию транскрипта. Они
   нужны и здесь, и в проверке шага 4. Потом пункты 1-3 раздела "Порядок" в
   `references/package.md`: десять пар `заголовок || ТЕКСТ ОБЛОЖКИ` в файле `yt-work/titles.txt`,
   один прогон

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/title.py yt-work/titles.txt
   ```

   и три лучших с твоим замечанием к каждому. Тот, который выбрал ты (а не тот, что инструмент
   напечатал первым), идёт в итоговый блок; два других - в альтернативы. Варианты пиши по
   транскрипту и под те же три запроса - иначе проверка в шаге 4 провалится.

   Если автор сказал оставить нынешнее название, десять вариантов не нужны. Прогони нынешнее:

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/title.py --title "нынешнее название"
   ```

   В ответ - только то, что проверка нашла (или что замечаний нет), без альтернатив. Если автор
   название не написал, а по ссылке ты его не видишь, - это тот самый один вопрос.

4. **Описание.** По разделу "Описание" в `references/publish.md`, в таком порядке:

   - первые две строки: что даёт видео, словами запроса - они видны до кнопки "ещё" и попадают в
     поиск;
   - строка с ссылкой на материалы, если автор что-то упоминал (код, файл, товар); нет - строки
     нет. Пиши `[ссылка]` вместо адреса, которого не знаешь, и не выдумывай адресов;
   - блок глав из шага 2 как есть;
   - длинная часть: что разобрано, для кого, что нужно знать заранее. Без обещаний того, чего в
     транскрипте нет;
   - последняя строка: до трёх хэштегов (шаг 5).

   **Проверка запросами** (раздел "Проверка запросами" в publish.md), по трём запросам из шага
   3, два условия на каждый запрос:

   - каждое значимое слово запроса (без предлогов и союзов, в любой форме) есть в названии или в
     первых двух строках описания. Нет - перепиши первые две строки, это твоя часть;
   - предмет запроса (то, о чём спрашивают: "обложка", "удержание", название инструмента) есть в
     самом названии. Описание этого не заменит: по запросу найдут, а по названию не кликнут. Нет -
     это проблема названия, а не описания. Своё название поправь и прогони ещё раз:

     ```bash
     python3 ${CLAUDE_SKILL_DIR}/scripts/title.py --title "..." --thumb "..."
     ```

     Про оставленное нынешнее скажи автору прямо, слова какого запроса в нём нет.

5. **Теги и хэштеги.** Теги - по разделу "Теги" в publish.md: только написания того, о чём видео
   (название инструмента латиницей и кириллицей, сокращение, транслит, частая опечатка), до
   пятнадцати, через запятую одной строкой. Тема, которой в видео нет, в теги не идёт - это
   нарушение правил площадки. Хэштеги - до трёх, каждый одним словом без пробелов, только слова
   темы, последней строкой описания: YouTube показывает их над названием.

## Что отдать

Сначала один блок для копирования целиком, в порядке полей страницы видео в Studio (вкладка
"Сведения"; в его версии названия полей могут отличаться):

```
НАЗВАНИЕ
...

ТЕКСТ НА ОБЛОЖКУ
...

ОПИСАНИЕ
первые две строки
[ссылка] - если есть
0:00 Глава
...
длинная часть
#тег #тег

ТЕГИ
тег, тег, тег
```

Текст на обложку - для картинки, а не для поля Studio; поле тегов - под описанием, за кнопкой
"Показать больше". Если название оставлено нынешнее, в блоке его нет, и текст обложки - только
если автор просил.

Потом, вне блока:

- два других названия из тройки, у каждого своё замечание словами: что обещает, что останется на
  телефоне, в чём риск; без баллов;
- три запроса, под которые собрано;
- "насколько этому верить", по одной фразе на пункт и только те, что есть: субтитры
  автоматические - имена и термины сверь; главы - черновик по паузам и смене слов, границы
  пересмотри с открытым видео; `[ссылка]` - заменить или удалить строку; что ещё проверка нашла
  в нынешнем названии, если его оставили.

Если видео уже выложено (дана ссылка), после ответа предложи одной фразой записать название и
обложку на будущее сравнение - как в конце `references/package.md`, без имён файлов. Если дан
только файл субтитров и видео ещё не вышло, предложи это, когда автор скажет, что оно вышло.
