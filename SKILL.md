# yt-studio

Один скилл, двенадцать режимов. Инструменты лежат в `${CLAUDE_SKILL_DIR}/scripts/` (Python 3 без
зависимостей), инструкция каждого режима - в `${CLAUDE_SKILL_DIR}/references/`. Читай только файл
нужного режима, не все сразу.

## Режимы

| Запрос пользователя | Прочитай | Инструмент |
| --- | --- | --- |
| оформить видео, название+описание+теги+таймкоды, подготовь к публикации | `references/format.md` | `title.py`, `chapters.py`, `fetch.py` |
| сценарий, хук, первая фраза | `references/script.md` | `hook.py`, `speech.py` |
| заголовок, обложка, низкий CTR | `references/package.md` | `title.py` |
| вырезать паузы, подсушить запись | `references/edit.md` | `cuts.py` |
| почему уходят, график удержания | `references/retention.md` | `retention.py` |
| что заходит в нише, конкуренты | `references/niche.md` | `fetch.py`, `outliers.py` |
| нарезать Shorts из длинного | `references/shorts.md` | `hook.py`, `retention.py` |
| описание, теги, главы | `references/publish.md` | `chapters.py` |
| комментарии, план недели, аудит, журнал | `references/channel.md` | `journal.py` |
| "что ты умеешь", "не работает" | этот файл, раздел "Знакомство и неполадки" | `doctor.py` |

"Подготовь видео к публикации" про уже снятое или загруженное видео - это один режим,
`references/format.md`. Если же запрос покрывает несколько режимов с нуля ("придумай видео и доведи
до выхода"), иди по порядку: сценарий -> упаковка -> описание и главы -> запись в журнал.

## Знакомство и неполадки

Пользователь не обязан знать, как устроен скилл. Если он пришёл с конкретной задачей - делай
задачу, этот раздел не нужен. Он нужен только в трёх случаях: пользователь спрашивает, что тут
можно делать; инструмент не запустился; для задачи не хватает необязательной программы. Тогда:

1. Запусти `python3 ${CLAUDE_SKILL_DIR}/scripts/doctor.py` и перескажи результат по-человечески:
   что готово, чего нет и что это отключает. Не вываливай вывод целиком.
2. На вопрос "что ты умеешь" отвечай коротко: пять-шесть возможностей одной строкой каждая и три
   способа начать прямо сейчас - дать идею видео (получит варианты начала и сценарий), дать
   заголовок (получит разбор), дать ссылку на готовое видео или его субтитры (получит название,
   описание, теги и главы одним блоком, а по просьбе - список, что вырезать). Про отсутствующие программы - одной фразой и только то, что они дают.
3. Не требуй установки необязательных программ заранее. Предлагай их в тот момент, когда они
   понадобились, одной командой из вывода `doctor.py`, и только с согласия пользователя.

## Правила для всех режимов

1. **Сначала делай, потом спрашивай.** Если для работы хватает того, что пользователь уже дал, -
   работай. Уточняй только то, без чего результат будет неверным: длина видео для удержания,
   частота кадров или файл исходника для монтажного листа, выложено ли уже видео (от этого
   зависит, что ещё можно исправить), язык канала, если он неясен. Один вопрос, не анкета.
2. **Голос.** Прочитай `~/.claude/yt-studio/voice.md`, если он есть и заполнен (точный путь к
   личным файлам печатает `doctor.py`; переменная `YT_STUDIO_HOME` его меняет). Если его нет, а
   задача - писать текст от имени автора (сценарий, заголовок, первые фразы Shorts, ответы на комментарии), не
   останавливайся: сделай работу в нейтральном разговорном тоне и один раз за разговор скажи
   простыми словами, без имён файлов, что текст станет ближе к его манере, если ты соберёшь
   описание его стиля из текстов двух-трёх его видео. Согласится, или сам покажет, как говорит
   (хватит и одного абзаца, чтобы начать), - создай шаблон (`doctor.py --init`), заполни его сам,
   убери из него строки-подсказки и скажи, что описание сохранено, будет использоваться дальше
   и меняется по его просьбе. Инструменты читают voice.md сами;
   тебе его нужно прочитать, чтобы писать этим голосом. Для аналитических режимов (рез,
   удержание, ниша, главы) voice.md не нужен - не упоминай его.
3. **Никаких выдуманных цифр.** Нет числа, результата или источника - спроси или напиши фразу без
   него. Примеры в `data/hooks.json` - шаблоны формы, их цифры в текст не переносить.
4. **Инструмент ловит ошибки, выбираешь ты.** `hook.py` и `title.py` находят механические
   ошибки: штампы, воду, лишнюю длину, повторы, чужие слова. Качество они не меряют, и несколько
   вариантов без замечаний - норма. Выбор между ними обосновывай сам и словами: что обещает
   фраза, какой вопрос открывает, чем рискует. Пользователю не показывай баллы - скажи, что
   проверка нашла или что замечаний нет.
5. **Говори о точности данных.** Если транскрипт только по фразам, длина видео не задана, в канале
   мало видео для медианы - инструмент это напечатает. Передай это пользователю, не прячь.
6. **Один главный вывод.** Аналитический режим заканчивается одной правкой, которую делать первой,
   а не списком из двадцати. Остальное - по просьбе. Исключение: если находка уже закрыта тем,
   что сделано раньше в разговоре (обрыв удержания стоит на дубле, который убирает монтажный
   лист), скажи это одной фразой - связь между режимами ценнее краткости.
7. **Ничего не публикуется.** Скилл пишет и считает; загружает, публикует и отвечает сам автор.
   Тексты для публикации отдавай отдельным блоком, который можно скопировать целиком.
8. **Язык и тон.** Отвечай на языке пользователя; текст для видео - на языке канала (просьба
   на другом языке о видео на этом языке - значит, видео на нём). Объясняй без
   жаргона: вместо "CTR" при первом упоминании - "доля кликов по показам (CTR)". Не пересказывай
   внутреннюю кухню: пользователю не нужны имена скриптов, баллы линтера без пояснения и слова
   "линтер", "JSON", "EDL" без расшифровки. Если называешь пункт меню YouTube Studio или
   монтажки, скажи, где он находится, и что в его версии он может называться иначе.
9. **Режимы связаны.** Если в разговоре ролик уже сушили, главы и таймкоды Shorts считай по
   подсушенной версии (главы - `chapters.py --cuts`, любые другие моменты - `cuts.py --at`).
   Если выложена неподсушенная версия, скажи, что главы и таймкоды подойдут к ней только после
   такой же обрезки. Если чинили файл пользователя (кривые таймкоды) -
   работай с копией и скажи об этом одной фразой.

## Запуск инструментов

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/doctor.py
python3 ${CLAUDE_SKILL_DIR}/scripts/hook.py hooks.txt
python3 ${CLAUDE_SKILL_DIR}/scripts/speech.py script.md --target 5:00
python3 ${CLAUDE_SKILL_DIR}/scripts/title.py titles.txt --thumb "ТРИ СЛОВА"
python3 ${CLAUDE_SKILL_DIR}/scripts/cuts.py transcript.json
python3 ${CLAUDE_SKILL_DIR}/scripts/chapters.py transcript.vtt --target 7
python3 ${CLAUDE_SKILL_DIR}/scripts/retention.py retention.csv --duration 10:00
python3 ${CLAUDE_SKILL_DIR}/scripts/fetch.py captions "https://youtu.be/ID" --lang ru
python3 ${CLAUDE_SKILL_DIR}/scripts/outliers.py niche/chan1_videos.json niche/chan2.txt
python3 ${CLAUDE_SKILL_DIR}/scripts/journal.py add --title "..." --thumb "..."
python3 ${CLAUDE_SKILL_DIR}/scripts/journal.py report
```

- У всех есть `--json`; запуск без аргументов печатает справку.
- Рабочие файлы (варианты, списки резов, главы) складывай в папку `yt-work/` в текущей рабочей
  папке, а не рядом со скиллом и не во временные каталоги: пользователь должен их найти.
- Варианты хуков и заголовков записывай в файл по одному на строку и передавай файл: так не
  ломаются кавычки и все варианты проверяются за один запуск. Для заголовков строка может
  нести свою обложку: `заголовок || ТЕКСТ ОБЛОЖКИ`.
- Если в пути к скиллу есть пробелы, бери путь в кавычки.
- Нет `python3` (часто на Windows) - используй `python` или `py -3`.
- Если `${CLAUDE_SKILL_DIR}` не подставился, скрипты лежат в папке `scripts/` рядом с этим файлом.
- Ошибка инструмента - это одна строка с причиной. Прочитай её и исправь вход; не переписывай
  логику инструмента своими руками и не выдумывай его результат.

## Откуда брать входные данные

- **Транскрипт своего видео.** Есть ссылка и стоит yt-dlp - `fetch.py captions URL`. Есть файл
  записи и стоит whisper - `whisper video.mp4 --word_timestamps True --output_format json` (самый
  точный вариант для реза). Иначе попроси `.srt`/`.vtt`: в YouTube Studio это "Субтитры" -> три
  точки -> "Скачать". Таймкоды не угадывай.
- **Удержание.** Выгрузка из Studio, а если пользователь не может её сделать - точки, прочитанные
  с графика (скриншот): запиши их в файл по строке `время, процент`, не меньше восьми.
- **Ниша.** `fetch.py channel URL` на каждый канал, либо список, который пользователь написал в
  чат: сохрани его в `.txt` по строке `название — просмотры` (подробнее в `references/niche.md`).
- **Среда без домашней папки** (чат без доступа к диску): voice.md и журнал не сохраняются между
  разговорами - попроси вставить voice.md в чат и скажи об этом ограничении один раз.
